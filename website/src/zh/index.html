GRC 工程的数据层

JASCON 将标准、裁剪、风险、实施、评估和证明写成一张由类型化、内容寻址的 JSON 对象构成的图。适用性声明成为一项计算，机器检查成为另一方可以重新计算的结果，捆绑包重新打包之后，签名依然可以验证。

02 模型

文档成为图的一种呈现

十一种浅层对象类型，每个对象都有全局标识符、版本和两个 SHA-256 摘要。所有已实测框架都需要的内容位于固定的内核中；单个框架所需的内容则放在一个已注册、带 Schema 的分面（facet）中。

内核

每个条款的约束力、类型化的参数和期限、成员关系、别名、历史。

规范性且封闭。变更随版本发布。

分面

框架词汇：德语陈述语法、800-53A 目标、保护目标。

已注册，Schema 已锁定。不认识某个分面的工具会停止并说明原因。

注解

跟踪系统 ID、渲染提示、工具自身的记录信息。

不参与任何合规计算，也不计入语义摘要。

凡有可能，错误都被设计为无法表示。正文中的参数标记必须指向一个已声明的参数。裁剪操作按标识定位陈述，因此上游的勘误无法让它改指别处。

03 改变了什么

当合规数据可以被计算时，会带来什么

GRC 工程像对待任何其他工程制品一样对待合规：版本化、类型化、经过测试并签名。这需要程序能够推理的数据。下面列出八项影响，各附其机制和证据状态。第九项是机器检查，下一节专门介绍。

ISO/IEC 27001 6.1.3 d在两个捆绑包上实测

适用性声明成为一项计算

Risk 写明其责任人、处置决定以及承载该决定的条款。随后，原语 risk-coverage 会列出每一条没有任何已评估风险作为依据的已选要求。过去，审计人员只能从电子表格中抽样核查这一点。

机制：2.0.0 候选中的 Risk 类型。在示例捆绑包上，校验器报告已选 3 项、有依据 1 项、未覆盖 2 项，并指出是哪两项。

Mapping实测

映射对照是有作者的数据

Mapping 是一个独立的对象：源、目标、关系、置信度和出处，可以细化到单个陈述。第三方的映射对照不属于任何一个目录，可以进行版本管理、比对差异，也可以提出异议。

机制：采用 NIST IR 8477 的关系代码。1.0.0 语料库中有 1,008 个 Mapping。

Tailoring实测

经得起上游新版本的裁剪

Tailoring 按 Set 选择，按标识修改：这条要求、这个陈述、这个参数。加强不受限制；弱化则需要一条有记录的 Deviation（偏离），并依据情态动词的偏序进行检查。

机制：八种封闭的操作，确定性的解析，没有合并规则。

Attestation实测

重新打包后依然有效的签名

证明绑定的是语义摘要。重新缩进文件或添加跟踪系统 ID，判定为 Semantic Match；修改一个情态动词，判定则为 Tamper。

机制：包摘要基于字节计算，语义摘要基于规范化内容计算；DSSE 信封，Ed25519。请在下方亲自试试。

内核规则实测

有效即可检查

{param:} 标记必须指向一个已声明且有类型的参数。分面锁定自己的 Schema，并声明它会改变哪些计算。基于这些规则构建的转换器发现了 781 个列表值，某个正在使用的国家级目录把它们塞进了单个以逗号分隔的字符串中。

机制：封闭的结构、受约束的标记、失效即停止（fail-closed）的分面。

text实测

一条要求，所有语言

每个人类可读字段都是一个从 BCP 47 语言标签到文本的映射表。一条德英双语的要求是一个对象、一个标识符，而这正是 NIS2、DORA 和 CRA 在欧盟各官方语言之间所需要的。

机制：text 原语。Grundschutz++ 捆绑包带有 de。

Implementation在一个语料库上实测

有明确依据的继承

SaaS 构建在 PaaS 之上，PaaS 又构建在 IaaS 之上：每条继承边都写明上游组件及其所依赖的具体授权。责任按陈述分为提供方、客户、共担或继承。

机制：一条带 inherited-from 和 basis-ref 的 Implementation 边，逐个链接进行检查。

退出实测

退出路径是内置的

目录捆绑包可导出为 OSCAL 1.2.2，通过 NIST Schema 的校验，重新导入后摘要保持不变。参考校验器是一个 {{ n.python_lines }} 行的 Python 文件，一致性由公开的测试向量裁定。

机制：export_oscal.py、一致性测试语料库、Apache 2.0。

04 检查

当评估者是一台机器

以 0 或 1 退出的扫描器隐藏了它的阈值，也无视裁剪。Check 公开采集器上报的事实和作出判定的比较，运行记录则携带观测值。

第十一种类型，2.0.0 候选 {{ n.check_vectors }} 个测试向量在三个实现中通过
  • 由 Tailoring 设定合格线。判定条件绑定要求中的一个参数。收紧这个参数，昨天的观测值就会被重新判定，代码无需任何改动。
  • 判定会被重新计算。校验器对每个已记录的观测值重新求值判定条件，并拒绝结果不一致的记录行。
  • 成批的资源得到的是一个比例，而不是更宽松的判定。覆盖多个资源的检查，只有在每个资源都通过时才算通过。所有资源都会被评估，结果显示为“200 个中 12 个不满足（6%）”。
  • 实测适配度：ComplianceAsCode 中 CIS Ubuntu 24.04 配置文件的 510 条规则里，有 481 条适合声明式形式，其余 29 条仍需人工处理。

06 工具

无需服务器即可运行的应用

JASCON 应用是一组浏览器页面，无需构建步骤，也没有后端。您加载的捆绑包只保留在您的浏览器中。各标签页按工作顺序排列。

  • 导入 OSCAL 目录或 profile。Grundschutz++ 规则能够逐个对象地重现随附的捆绑包，以语义摘要为准。
  • 风险、裁剪、映射、实施、评估：每个页面都会把真实的对象写入工作集，并导出捆绑包，其中每个对象都带有两个摘要。
  • 草稿来自模型，判定来自内核。输入密钥后，有两个页面可以调用语言模型。草稿由内核规则评判，只有在您采纳时才会保存。
