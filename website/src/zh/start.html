快速开始

从一个浏览器标签页到一个通过校验的捆绑包

七个步骤，按大多数人采用的顺序排列。第一步需要一个浏览器，第二步需要 Python 或一台 Windows 计算机。任何一步都不需要账号、服务器或许可证密钥。

打开一个您熟悉的目录

应用通过链接加载捆绑包，并将其保存在您的浏览器中。从您日常使用的框架开始：对象浏览器根据数据构建筛选条件，因此 SP 800-53 提供控制族和基线，Grundschutz++ 则提供情态动词、保护目标和目标对象。

语料库对象数类型内容的许可

手册的示例捆绑包包含每种类型各一个对象，其中有一个 Risk、两个 Tailoring 和两个 Check：打开示例捆绑包。此外还有一个不需要外围文件夹的单文件阅读器；下载后，将捆绑包文件夹拖放到它上面即可。

运行参考校验器

校验器先运行 {{ n.vectors }} 个一致性测试向量，然后用两个摘要重新验证随附捆绑包中的每个对象。最后一行显示 ALL GREEN，或者逐条列出每一处失败及其规则和原因。

传入一个或多个捆绑包文件夹，即可校验您自己的内容。--require-risk-basis 会把没有风险作为理由的已选要求判为失败。

在 Windows 上，PowerShell 孪生实现无需安装任何东西，即可在 PowerShell 5.1 上完成同样的工作。Python 只需几秒钟，它则需要几分钟。

Python，使用 uv
git clone https://github.com/christoph-puppe/JASCON.git
cd JASCON
uv run --no-project --with jsonschema python jascon/scripts/validate_core.py
Python，使用 pip
pip install jsonschema
python jascon/scripts/validate_core.py
# your own bundle:
python jascon/scripts/validate_core.py path/to/your-bundle
Windows PowerShell 5.1，无需安装
powershell -ExecutionPolicy Bypass -File jascon\scripts\validate_core.ps1

编写第一个要求

在您控制的域名下选择一个前缀，并长期保持不变。标识符按字符串比较，从不联网获取，因此该地址无需提供任何内容。

在约束力、义务方或参数发生变化的地方，将文本拆分为多条陈述。为每个参数声明类型，并在正文中用 {param:name} 引用它。

应用的浏览（Browse）页面在“Write requirements and sets”下提供了用于此目的的表单。它会为正文中找到的参数生成声明。首页（Home）可将工作集导出为捆绑包，附带清单以及每个对象的两个摘要。

带入您的 OSCAL，也能再导出去

应用的导入（Import）页面读取 OSCAL catalog 或 profile，并报告它所应用的每一条规则。针对 Grundschutz++、SP 800-53 和 CIS Benchmarks 已有专用规则集；其他结构的目录则走通用规则：内核中没有对应字段的内容，会保存在您命名空间下的分面（facet）中，任何内容被丢弃时，报告中都会有相应的一行。用于批量处理时，仓库中有十一个 Python 转换器，每个实测语料库一个，共用一个公共库。

反方向上，export_oscal.py 可写出 OSCAL 1.2.2 目录。随附捆绑包的导出结果就放在它们旁边，位于 converted_examples/*/oscal-export/ 下。OSCAL 中没有对应构造的内容（情态、义务方、重叠的成员关系）借助带命名空间的 props 传递，并在导入时还原。

添加风险并计算覆盖

加载一个目录，用 Tailoring 选定基线，然后在风险（Risk）页面中写下作为该选择理由的风险。覆盖（Coverage）视图会列出所有未被任何已评估风险提及的已选要求。

两个原型风险目录可帮助您完成第一轮工作：办公 IT 的 24 个典型风险和工业设施的 23 个典型风险，提供英文和德文版本，每个风险都附有建议的 SP 800-53 控制措施。导入会将某个条目复制为您自己的 Risk；决定权仍在您手中。

编写机器检查

对于技术性规则，应用的检查（Checks）页面可以编写 Check（内核 2.0.0，发布候选版）：采集器报告的事实、作出判定的比较，以及采集器代码，可用 bash、sh、Python、PowerShell、Ansible 编写，或采用 HTTP 请求的形式。输入密钥后，语言模型即可起草检查，既可一次一条规则，也可针对一次 CIS 导入中的全部自动化规则。每份草稿都由内核规则和只读 lint 进行评判，保存哪些由您决定。应用不运行采集器。

引入厂商的建议

建议包是厂商发布的一个文件：其中是针对具名要求提出建议的 Component（内核 2.0.0，发布候选版）。应用的首页会在写入任何内容之前展示包中的内容，说明其发布方是仅为声称、有证明还是已证实，并在导入后输出一份回执。在实施（Implement）页面上，您将该产品设为您系统的成员，并把一条建议采纳为您自己的边。同一文件第二次导入时不会写入任何内容。

示例包是虚构的，以公开的测试密钥签名。目前尚无厂商发布过建议包。

在应用中预览示例包   建议包如何运作

面向厂商：编写建议包

建议包构建器是一个可离线运行的 HTML 文件。您在表单中描述自己的产品和每一条建议；页面使用与客户导入时相同的规则检查该包，用您的 Ed25519 密钥为该版本签名，或为 openssl 或您的签名服务准备好待签名的字节，并生成 ZIP 文件。加载目录后，它会列出每个要求的条款和参数供您选择，并检查每一个建议值。您已有的 OSCAL 组件定义会作为草稿导入，并附一份报告，说明哪些内容无法安置。

与编码智能体协作

文件夹 jascon/ 是一个供 Claude 使用的技能（skill）：其中包括以十四条编号要求形式呈现的手册、内核 Schema、一致性测试向量、转换器以及一个完整的示例捆绑包。拥有它的智能体会依据 Schema 编写对象，并对自己的输出运行校验器。

分工与应用中的相同：模型起草，内核规则判定，由人确认接受。

安装技能
# for your user
cp -r jascon ~/.claude/skills/jascon
# or for one project
cp -r jascon .claude/skills/jascon
