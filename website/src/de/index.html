Offene Notation · Apache 2.0

Die Datenschicht für GRC-Engineering

JASCON schreibt Standards, Tailoring, Risiken, Umsetzungen, Prüfungen und Attestierungen als einen einzigen Graphen typisierter, inhaltsadressierter JSON-Objekte. Eine Erklärung zur Anwendbarkeit (SoA) wird zur Berechnung, eine maschinelle Prüfung zu etwas, das eine zweite Partei nachrechnen kann, und eine Signatur lässt sich auch dann noch verifizieren, wenn das Bundle neu verpackt wurde.

02 Das Modell

Dokumente werden zu Darstellungen eines Graphen

Elf flache Objekttypen, jeder mit einem globalen Bezeichner, einer Version und zwei SHA-256-Digests. Was jedes gemessene Framework braucht, liegt in einem festen Kern. Was ein einzelnes Framework braucht, liegt in einer registrierten Facette mit Schema.

Kern

Verbindlichkeit je Klausel, typisierte Parameter und Fristen, Mitgliedschaft, Aliasse, Historie.

Normativ und geschlossen. Änderungen kommen nur mit einer neuen Version.

Facetten

Vokabular eines Frameworks: die deutsche Satzgrammatik der Anforderungen, die Prüfziele aus 800-53A, Schutzziele.

Registriert, mit fixiertem Schema. Ein Tool, das eine Facette nicht kennt, hält mit Begründung an.

Annotationen

Tracker-IDs, Darstellungshinweise, interne Buchführung von Tools.

Außerhalb jeder Compliance-Berechnung und außerhalb des semantischen Digests.

Wo es möglich ist, sind Fehler gar nicht erst darstellbar. Ein Parameter-Token im Fließtext muss einen deklarierten Parameter benennen. Eine Tailoring-Operation adressiert eine Aussage über deren Identität, sodass ein Erratum des Herausgebers sie nicht auf etwas anderes umlenken kann.

03 Was sich ändert

Was folgt, wenn man mit Compliance-Daten rechnen kann

GRC-Engineering behandelt Compliance wie jedes andere Engineering-Artefakt: versioniert, typisiert, getestet und signiert. Dafür braucht es Daten, über die ein Programm schlussfolgern kann. Acht Konsequenzen, jede mit ihrem Mechanismus und dem Stand ihrer Nachweise. Eine neunte, die maschinelle Prüfung, hat den nächsten Abschnitt für sich.

ISO/IEC 27001 6.1.3 dan zwei Bundles gemessen

Die Erklärung zur Anwendbarkeit wird zur Berechnung

Ein Risk benennt seinen Eigentümer, seine Behandlungsentscheidung und die Klauseln, die diese Entscheidung tragen. Das Primitiv risk-coverage listet dann jede ausgewählte Anforderung auf, die auf keinem bewerteten Risiko beruht. Bisher hat ein Auditor das anhand von Stichproben aus einer Tabelle geprüft.

Mechanismus: der Typ Risk des Kandidaten für 2.0.0. Für das Beispiel-Bundle meldet der Validator 3 ausgewählt, 1 begründet, 2 nicht abgedeckt und benennt die beiden.

Mappinggemessen

Ein Crosswalk ist ein Datensatz mit Autor

Ein Mapping ist ein eigenes Objekt: Quelle, Ziel, Beziehung, Konfidenz und Herkunft, bis hinunter zur einzelnen Aussage. Der Crosswalk eines Dritten gehört zu keinem der beiden Kataloge und lässt sich versionieren, per Diff vergleichen und anfechten.

Mechanismus: Beziehungscodes aus NIST IR 8477. 1.008 Mappings im Korpus von 1.0.0.

Tailoringgemessen

Tailoring, das ein neues Release des Herausgebers übersteht

Ein Tailoring wählt über Sets aus und ändert über Identität: diese Anforderung, diese Aussage, dieser Parameter. Verschärfen ist ohne Weiteres erlaubt. Abschwächen erfordert eine dokumentierte Deviation und wird gegen eine Halbordnung der Modalverben geprüft.

Mechanismus: acht geschlossene Operationen, deterministische Auflösung, keine Merge-Regeln.

Attestationgemessen

Eine Signatur, die ein Umverpacken übersteht

Eine Attestierung bindet semantische Digests. Rücken Sie eine Datei neu ein oder fügen Sie eine Tracker-ID hinzu, lautet das Urteil Semantic Match. Ändern Sie ein Modalverb, lautet es Tamper.

Mechanismus: Paket-Digest über die Bytes, semantischer Digest über den kanonischen Inhalt; DSSE-Envelope, Ed25519. Unten ausprobieren.

Kernregelngemessen

Gültig heißt prüfbar

Ein {param:}-Token muss einen deklarierten, typisierten Parameter benennen. Eine Facette fixiert ihr Schema und deklariert, welche Berechnungen sie verändert. Der auf diesen Regeln aufgebaute Konverter fand 781 Listenwerte, die ein produktiv genutzter nationaler Katalog in einzelne kommagetrennte Strings packt.

Mechanismus: geschlossene Strukturen, gebundene Tokens, Facetten nach dem Fail-Closed-Prinzip.

textgemessen

Eine Anforderung, jede Sprache

Jedes für Menschen lesbare Feld ist eine Map von BCP-47-Sprachtag auf Text. Eine Anforderung auf Deutsch und Englisch ist ein Objekt mit einem Bezeichner, und genau das werden NIS2, DORA und der CRA über die Amtssprachen der Union hinweg brauchen.

Mechanismus: das Primitiv text. Das Bundle für Grundschutz++ enthält de.

Implementationan einem Korpus gemessen

Vererbung mit benannter Grundlage

Ein SaaS auf einem PaaS auf einem IaaS: Jede geerbte Kante benennt die vorgelagerte Komponente und die konkrete Autorisierung, auf die sie sich stützt. Die Verantwortung ist je Aussage typisiert, als Anbieter, Kunde, geteilt oder geerbt.

Mechanismus: eine Implementation-Kante mit inherited-from und basis-ref, Glied für Glied geprüft.

Ausstieggemessen

Der Ausstieg ist eingebaut

Katalog-Bundles lassen sich nach OSCAL 1.2.2 exportieren; der Export validiert gegen das Schema von NIST und ergibt beim Reimport dieselben Digests. Der Referenzvalidator ist eine Python-Datei mit {{ n.python_lines }} Zeilen, und über Konformität entscheiden öffentliche Vektoren.

Mechanismus: export_oscal.py, das Konformitätskorpus, Apache 2.0.

04 Checks

Wenn eine Maschine prüft

Ein Scanner, der mit 0 oder 1 endet, verbirgt seinen Schwellenwert und ignoriert das Tailoring. Ein Check veröffentlicht die Fakten, die ein Kollektor meldet, und die Vergleiche, die entscheiden, und der Datensatz des Laufs enthält die Beobachtung.

elfter Typ, Kandidat für 2.0.0 {{ n.check_vectors }} Vektoren bestehen in drei Implementierungen
  • Das Tailoring legt die Bestehensgrenze fest. Die Kriterien binden einen Parameter der Anforderung. Verschärfen Sie ihn, wird die Beobachtung von gestern neu beurteilt, ohne Änderung am Code.
  • Ein Urteil wird nachgerechnet. Der Validator wertet die Kriterien für jede aufgezeichnete Beobachtung aus und weist eine Zeile zurück, deren Ergebnis abweicht.
  • Eine Flotte erhält einen Anteil, nie ein milderes Urteil. Ein Check über viele Ressourcen ist nur bestanden, wenn jede einzelne besteht. Alle werden ausgewertet, und das Ergebnis lautet „12 von 200 nicht erfüllt (6 %)“.
  • Gemessene Passung: 481 der 510 Regeln in den CIS-Profilen für Ubuntu 24.04 von ComplianceAsCode passen in die deklarative Form. Die übrigen 29 bleiben manuell.

06 Das Werkzeug

Eine funktionierende App ohne Server

Die JASCON-App besteht aus Browserseiten ohne Build-Schritt und ohne Backend. Ein Bundle, das Sie laden, bleibt in Ihrem Browser. Die Reiter folgen der Reihenfolge der Arbeit.

  • Importieren (Import) liest einen OSCAL-Katalog oder ein OSCAL-Profil ein. Die Regeln für Grundschutz++ reproduzieren das mitgelieferte Bundle Objekt für Objekt, gemessen am semantischen Digest.
  • Risiko (Risk), Tailoring (Tailor), Mapping (Map), Umsetzen (Implement), Prüfen (Assess): Jede dieser Seiten schreibt echte Objekte in den Arbeitsbestand und exportiert ein Bundle mit beiden Digests je Objekt.
  • Entwürfe vom Modell, Urteile vom Kern. Zwei Seiten können ein Sprachmodell befragen, sobald Sie einen Schlüssel eingeben. Ein Entwurf wird von den Kernregeln beurteilt und erst gespeichert, wenn Sie ihn übernehmen.

08 Für wen

Vier Rollen, je ein erster Schritt

Jeder dieser Schritte kostet einen Tag und braucht niemandes Erlaubnis.

Sie veröffentlichen ein Framework

Behörden und Normungsgremien

Ihr Katalog behält seine Struktur. Baselines werden zu Sets, Varianten zu Tailorings, Ihr Vokabular wird zu einer Facette mit Schema.

Erster SchrittWählen Sie einen Namespace, schreiben Sie ein Set und kodieren Sie zehn Anforderungen neu. Oder öffnen Sie Ihren Katalog auf der Seite Importieren (Import).

Sie bauen Tools

GRC-Hersteller und Plattformteams

Ein JSON Schema, eine Serialisierung, zehn Primitive mit einer Begründung, die bei einem Fehler ausgegeben wird. Kein Metaschema und keine Profilauflösung.

Erster SchrittKlonen Sie das Konformitätskorpus und schreiben Sie einen Validator in Ihrer Sprache. Die Vektoren sind der Schiedsrichter.

Sie verantworten Compliance

GRC-Engineers, CISOs, ISMS-Verantwortliche

Ihr Risikoregister, Ihre Erklärung zur Anwendbarkeit, Ihre Umsetzungsbeschreibungen und Feststellungen als Dateien in einem Repository, die wie Code reviewt werden.

Erster SchrittLaden Sie SP 800-53 oder Grundschutz++ in die App, schreiben Sie drei Risiken und lesen Sie die Abdeckung ab.

Sie prüfen oder kaufen ein

Auditoren, Prüfer, Einkauf

Sie verifizieren auf Ihrem eigenen Rechner und offline, was genehmigt wurde. Der PowerShell-Validator braucht einen Windows-Rechner im Auslieferungszustand und sonst nichts.

Erster SchrittBitten Sie einen Lieferanten um ein Bundle und lassen Sie den Validator darüber laufen. Behandeln Sie eine Konformitätsaussage ohne Ergebnisse aus dem Korpus wie ein Datenblatt.

Ein Maintainer und noch kein Nutzer von außen
