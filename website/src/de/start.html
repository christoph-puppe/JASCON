Erste Schritte

Vom Browser-Tab zum validierten Bundle

Sieben Schritte, in der Reihenfolge, in der die meisten sie gehen. Der erste braucht einen Browser. Der zweite braucht Python oder einen Windows-Rechner. Keiner braucht ein Konto, einen Server oder einen Lizenzschlüssel.

Einen Katalog öffnen, den Sie kennen

Die App lädt ein Bundle über einen Link und behält es in Ihrem Browser. Beginnen Sie mit dem Framework, mit dem Sie arbeiten: Der Objektbrowser bildet seine Filter aus den Daten, deshalb bietet SP 800-53 Familien und Baselines an und Grundschutz++ Modalverben, Schutzziele und Zielobjekte.

Den Referenzvalidator ausführen

Der Validator führt die {{ n.vectors }} Konformitätsvektoren aus und prüft danach jedes Objekt der mitgelieferten Bundles erneut mit beiden Digests. Die letzte Zeile lautet ALL GREEN oder listet jeden Fehlschlag mit seiner Regel und seinem Grund auf.

Übergeben Sie einen oder mehrere Bundle-Ordner, um eigene Inhalte zu validieren. --require-risk-basis macht aus einer ausgewählten Anforderung ohne begründendes Risiko einen Fehlschlag.

Unter Windows erledigt der PowerShell-Zwilling dasselbe mit PowerShell 5.1, ohne dass etwas installiert werden muss. Er braucht Minuten, wo Python Sekunden braucht.

Python, mit uv
git clone https://github.com/christoph-puppe/JASCON.git
cd JASCON
uv run --no-project --with jsonschema python jascon/scripts/validate_core.py
Python, mit pip
pip install jsonschema
python jascon/scripts/validate_core.py
# Ihr eigenes Bundle:
python jascon/scripts/validate_core.py path/to/your-bundle
Windows PowerShell 5.1, ohne Installation
powershell -ExecutionPolicy Bypass -File jascon\scripts\validate_core.ps1

Eine erste Anforderung schreiben

Wählen Sie ein Präfix unter einer Domain, die Sie kontrollieren, und behalten Sie es bei. Kennungen werden als Zeichenketten verglichen und nie abgerufen, deshalb muss unter der Adresse nichts ausgeliefert werden.

Teilen Sie den Text dort in Aussagen auf, wo sich die Verbindlichkeit, die verpflichtete Partei oder ein Parameter ändert. Deklarieren Sie jeden Parameter mit einem Typ und verweisen Sie im Fließtext mit {param:name} darauf.

Die Seite Browse der App hat dafür ein Formular unter „Write requirements and sets“. Es deklariert die Parameter, die es im Fließtext findet. Die Seite Home exportiert den Arbeitsbestand als Bundle mit Manifest und beiden Digests je Objekt.

Bringen Sie Ihr OSCAL mit und nehmen Sie es wieder mit

Die Seite Import der App liest einen OSCAL-Katalog oder ein OSCAL-Profil und meldet jede Regel, die sie angewandt hat. Regelsätze gibt es für Grundschutz++, SP 800-53 und CIS Benchmarks; ein Katalog anderer Form läuft durch die generischen Regeln, die das, wofür der Kern kein Feld hat, in einer Facette unter Ihrem Namespace bewahren und nichts verwerfen, ohne dass der Bericht eine Zeile dazu enthält. Für die Stapelverarbeitung enthält das Repository elf Konverter in Python, einen je gemessenem Korpus, auf Basis einer gemeinsamen Bibliothek.

In der Gegenrichtung schreibt export_oscal.py Kataloge in OSCAL 1.2.2. Die Exporte der mitgelieferten Bundles liegen daneben unter converted_examples/*/oscal-export/. Wofür OSCAL kein Konstrukt hat (Modalität, verpflichtete Parteien, überlappende Mitgliedschaft), reist in Props mit Namespace mit und kommt beim Import zurück.

Risiken ergänzen und die Abdeckung berechnen

Laden Sie einen Katalog, wählen Sie mit einem Tailoring eine Baseline aus und schreiben Sie auf der Seite Risk die Risiken, die die Auswahl begründen. Die Ansicht Coverage listet jede ausgewählte Anforderung auf, die kein bewertetes Risiko nennt.

Zwei prototypische Risikokataloge helfen beim ersten Durchgang: 24 typische Risiken der Büro-IT und 23 einer Industrieanlage, auf Englisch und Deutsch, jeweils mit vorgeschlagenen Controls aus SP 800-53. Der Import kopiert einen Eintrag in ein eigenes Risk; die Entscheidung bleibt bei Ihnen.

Eine maschinelle Prüfung schreiben

Für eine technische Regel schreiben Sie auf der Seite Checks der App einen Check (Kern 2.0.0, Release-Kandidat): die Fakten, die ein Kollektor meldet, die Vergleiche, die entscheiden, und den Code des Kollektors in bash, sh, Python, PowerShell, Ansible oder als HTTP-Anfrage. Ein Sprachmodell kann Checks entwerfen, Regel für Regel oder für jede automatisierte Regel eines CIS-Imports, sobald Sie einen Schlüssel eingeben. Jeder Entwurf wird von den Kernregeln und einem Lint, der nur liest, beurteilt, und Sie entscheiden, was gespeichert wird. Die App führt keine Kollektoren aus.

Die Empfehlungen eines Herstellers aufnehmen

Ein Empfehlungspaket ist eine Datei, die ein Hersteller veröffentlicht: Components mit Empfehlungen zu benannten Anforderungen (Kern 2.0.0, Release-Kandidat). Die Seite Home der App zeigt, was ein Paket enthält, bevor etwas geschrieben wird, sagt, ob sein Herausgeber behauptet, attestiert oder belegt ist, und gibt nach dem Import eine Quittung aus. Auf der Seite Implement machen Sie das Produkt zum Mitglied Ihres Systems und übernehmen eine Empfehlung als Ihre eigene Kante. Dieselbe Datei ein zweites Mal schreibt nichts.

Das Beispielpaket ist fiktiv und mit einem öffentlichen Testschlüssel signiert. Noch hat kein Hersteller ein Paket veröffentlicht.

Vorschau des Beispielpakets in der App   Wie ein Paket funktioniert

Für Hersteller: ein Paket schreiben

Der Paket-Builder ist eine einzelne HTML-Datei, die offline läuft. Sie beschreiben Ihr Produkt und jede Empfehlung in einem Formular; die Seite prüft das Paket mit denselben Regeln, die der Import beim Kunden ausführt, signiert die Ausgabe mit Ihrem Ed25519-Schlüssel oder bereitet die Bytes für openssl oder Ihren Signaturdienst vor und schreibt das ZIP. Ist der Katalog geladen, bietet sie die Klauseln und Parameter jeder Anforderung an und prüft jeden vorgeschlagenen Wert. Eine OSCAL-Komponentendefinition, die Sie bereits haben, wird als Entwurf importiert, mit einem Bericht darüber, was sich nicht zuordnen ließ.

Mit einem Coding-Agenten arbeiten

Der Ordner jascon/ ist ein Skill für Claude: das Handbuch als vierzehn nummerierte Anforderungen, das Kernschema, die Konformitätsvektoren, die Konverter und ein ausgearbeitetes Beispiel-Bundle. Ein Agent, der ihn hat, schreibt Objekte gegen das Schema und lässt den Validator über seine eigene Ausgabe laufen.

Die Arbeitsteilung ist dieselbe wie in der App: Ein Modell entwirft, die Kernregeln entscheiden, ein Mensch nimmt an.

den Skill installieren
# für Ihren Benutzer
cp -r jascon ~/.claude/skills/jascon
# oder für ein einzelnes Projekt
cp -r jascon .claude/skills/jascon
