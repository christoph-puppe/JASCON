Checks · change proposal CP-CHECK-1

When the assessor is a machine

A scanner that exits with 0 or 1 hides its threshold, ignores the tailoring and leaves nothing to re-examine. A Check publishes the facts a collector must report and the comparisons that decide. The run record carries what was observed, so anyone recomputes the verdict from the record.

01 The gap

The automation exists at the publisher and is lost on the way

JASCON 1.0.0 can say that a requirement was assessed and what the assessor concluded. It cannot say how a machine decides.

291 of 312

rules of the CIS Ubuntu 24.04 Benchmark are marked automated

Every one of them arrives in a converted bundle as an audit string with shell excerpts in prose. The pass condition is a sentence such as "verify the output is", which a person has to read.

0 of 3

census authorities encode a machine-decidable check

The ISM, Grundschutz++ and SP 800-53 name methods (examine, interview, test) and required documentation. FedRAMP CR26 carries key tests as prose. None of them specifies a check a program can evaluate.

Counts: CP-CHECK-1, section 2.1, from the coverage reports of the converted corpora.

02 The design

The collector observes, the criteria decide

The line is drawn where tools must agree. Two conformant tools given the same Check and the same observation return the same verdict. Everything that may differ between honest tools without changing the verdict stays outside the kernel.

Facet, outside the kernel

Collector

A shell script, an Ansible task or an API call, carried on the Check so that the check's digest covers the exact code. It prints one observation and decides nothing.

Kernel: the fact contract

Observation

Named, typed facts such as sshd.maxauthtries: integer. A collector reports effective values, with defaults resolved. An absent key means "looked and did not find".

Kernel: eleven comparators

Criteria

A flat conjunction such as at-most {param}. The expected value is a literal or a parameter of the requirement, so the Tailoring that binds the parameter sets the pass mark.

Kernel: check-verdict

Verdict

Satisfied, not satisfied, inconclusive or not applicable: a pure function of the Check, the observation and the bound parameters. The validator recomputes every recorded verdict.

A tailored parameter retunes the check

Tighten max-auth-tries from 6 to 4 in the Tailoring, and yesterday's observation of 5 turns from satisfied to not satisfied. No line of code changes, and an implementer cannot set its own pass mark.

A verdict is recomputed, never trusted

The Assessment row holds the observation itself. A second party evaluates the criteria on it and compares. A recorded outcome that differs from the computed one is a validation error.

The record shows what was observed

A failing row reads sshd.ciphers matches-not ".*-cbc", observed a list that contains aes128-cbc. An exit code would have said 1.

04 The comparators

Eleven, and a list of what is left out

The set is small on purpose. A check that does not fit stays manual and is counted.

  • The criteria are a conjunction. There is no OR, no NOT and no nesting; alternatives of a value are one-of, and negation lives in the operator pairs.
  • No arithmetic and no comparison between two facts. Counting and deriving are work of the collector.
  • The combination is strong Kleene AND: one definite failure decides, and a failure is never hidden behind an unknown elsewhere.
  • An unbound parameter gives inconclusive. A default is never substituted.
  • at-most never binds a parameter that tightens upward, so that tightening a parameter cannot loosen a check.

Why a regular expression is allowed

The handbook rejects expression languages, because two conformant tools may then return two verdicts. Python, .NET and JavaScript disagree on exactly the constructs people reach for: \d, \w, anchors, flags, lookaround. The dialect is therefore I-Regexp (RFC 9485), built by the IETF for interoperability and used by JSONPath.

What the kernel fixes beyond the RFC

  • A pattern matches the whole value. ^ and $ are ordinary characters.
  • Limits: 256 characters per pattern, 1,000 states, 4,096 characters per value. Beyond that the row is inconclusive.
  • No host engine. Each implementation parses the grammar itself and matches without backtracking, so a pattern cannot stall a validator.
  • One dependence is left and stated: a Unicode category \p{..} is read from the host's database (backlog 59).

05 Evidence

Every link verifies offline

Evidence is a directory beside the content manifest. Every file is named by the SHA-256 of its bytes. Redaction happens before hashing, and raw output is a separate file, so a retention delete leaves the record verifiable: the validator reports the file as withheld.

Attestation

binds the semantic digest of the Assessment.

Assessment row

holds the observation inline, so that digest covers it. It names the Check by reference and by digest: a changed check is a different check.

Evidence record

names the check, the collector, the subject, start, end and exit status, and carries the digest of the same observation.

Raw outputs

stdout or an API response, each by digest, with media type, size and a redaction flag.

06 Measured fit

481 of 510 rules fit the declarative form

The comparator set was drafted first and measured afterwards, against two open check corpora: the four CIS profiles for Ubuntu 24.04 in ComplianceAsCode (510 rules) and the CIS 1.12 checks of kube-bench (103 automated, 28 manual).

What the census shows measured, fit by judgement

  • The comparison side is small and the logic sits on the collection side. In 126 hand-written OVAL definitions the states compare with equals 99 times, with a pattern 23 times and with an ordering 41 times.
  • Of 491 regular expressions, 23 are on the comparison side. All 23 are inside I-Regexp or can be rewritten mechanically.
  • Of the 21 OR checks in kube-bench, 16 read "flag absent or flag equals value". A collector that reports the effective value turns them into one comparison.

What it contradicts

There is no not-equal. It occurs twice in the OVAL states and 85 times across all kube-bench directories. A twelfth comparator is measured and cheap, and it is an open decision. The 29 rules that do not fit stay manual.

07 State

Implemented and green, proposed and undecided

The type is in the schema of the 2.0.0 release candidate and in all three implementations. It is in no released kernel, and the decision to admit it is open.

In the repository

measured
  • Schema: the Check shape, the run rows on Assessment, the reference on Finding, the evidence record, and the facet collector@1.
  • Rules: CHECK-1 to CHECK-15 and the primitive check-verdict, each with a rationale that prints on failure.
  • {{ n.check_vectors }} conformance vectors: passed by the Python reference, by the PowerShell twin on Windows PowerShell 5.1, and by the JavaScript port in the app.
  • A worked example with two Checks, two runs, a Finding and seven evidence files.
  • The app's Checks page: writes checks by hand or lets a language model draft them, one rule at a time or for every automated rule of a CIS import. A draft is judged by the kernel rules and a read-only lint and saved only when you take it.

Missing or undecided

open
  • No runner. Nothing in the repository executes a collector on a target. The app does not run collectors either.
  • No cloud platform measured. The census covers Linux hosts and Kubernetes. A corpus of checks against cloud APIs has not been counted.
  • The promotion rule fails. A semantic enters the kernel when two of three census authorities encode it. Here none does. Check would be the second recorded exception after Risk.
  • Handbook and specification text for the type are drafted in the proposal and not yet merged. The single-file reader cannot open a bundle with a Check.
  • Seven points wait for a decision, among them the not-equal comparator, run rows as kernel field or facet, and whether a check may ship without the catalogue it refers to.

The proposal in full, with the alternative that was not taken (criteria in a facet, promotion later): drafts/CP-CHECK-1.md.

Review it before the shape is closed

A kernel type is paid for by every validator for ever, and a correction after the tag costs a major version. The proposal needs readers who run scanners for a living: does the fact contract hold for your platform, and which of your checks falls outside eleven comparators?
