The model

Ten object types and what each one replaces

The kernel holds what three national frameworks were measured to need and nothing else. This page walks through it once. The normative text is the specification; the long form with every count is the handbook.

01 The smallest object

A complete requirement

This is a whole object, with no props, no facets and no document around it. The handbook uses it as its first example because the entire extension surface of the Australian ISM needs nothing more.

  • id is a URI under the authority's own domain. It is compared as a string and never fetched, so validation works on a sealed network.
  • version and two digests in the manifest carry the history. The ISM maintains 2,202 revision props by hand for the same purpose.
  • statements is a list because clauses are real: Grundschutz++ contains 347 nested pseudo-controls that exist only to make clauses addressable.
  • modality and obligated-parties sit on the statement. One requirement can bind the operator with MUST and the customer with SHOULD.
  • prose is a map from language tag to text.

02 The types

Each type exists because a published catalogue demanded it

Nine types are in the released 1.0.0. Risk is the tenth, in the 2.0.0 release candidate. Check is a proposal. The right column says what the type takes over from OSCAL 1.x or from common practice.

Content: what is required

Requirement

One control, rule or criterion as a list of identified statements. Each statement has a modality, obligated parties, typed parameters and prose. Guidance and objectives are statements too, with the modality unspecified, or they sit in a framework facet.

Takes overCatalog controls and their parts; the label, alt-identifier and sort-id props.

RequirementSet

Membership, and nothing else. A Set lists requirements or other Sets with a sequence number. Chapters, families, baselines, maturity levels and classification markers are all Sets, and a requirement may be in many.

Takes overGroups, the resolved-profile baselines, and the 5,301-entry applicability matrix of the ISM.

Tailoring

A selection plus a closed list of eight operations, each addressed by identity: requirement, statement, parameter. Nothing is copied. Resolution is one deterministic pass; there are no merge rules because global identifiers make them unnecessary.

Takes overProfiles and the profile-resolution specification; inline per-class variants as in FedRAMP CR26.

Mapping

One crosswalk edge in nine flat fields: source, target, optional statement scope, relationship, direction, confidence, rationale, provenance. Relationship codes follow NIST IR 8477, plus supplements for content attached to a foreign catalogue.

Takes overThe control mapping model of OSCAL 1.2; crosswalk spreadsheets.

Organisation: why it is in scope

Risk 2.0.0-rc.1

The record ISO/IEC 27001 6.1.2 and 6.1.3, BSI Standard 200-3 and NIST SP 800-30 all require: a scenario, an owner, a state, a rating as a level on a named scale, one of four treatment options, and the clauses that carry the treatment. Scoring methods stay outside the kernel. A Risk justifies a requirement once it is assessed and its option chosen.

Takes overThe risk register as a spreadsheet and the Statement of Applicability as a document. risk-coverage computes the latter.

Systems: what is in place and what was found

Component

A product, service, policy, process or a system, which is a component with members. Authorization boundaries are identified objects on the component. An absent boundary asserts nothing.

Takes overComponent definitions and the system description of the SSP.

Implementation

One edge: this component satisfies that requirement, optionally that statement, in this way. Responsibility is provider, customer, shared or inherited. An inherited edge must name the upstream component and the authorization it leans on, so a SaaS on a PaaS on an IaaS is checked link by link.

Takes overThe implemented requirements of the SSP and the control implementations of component definitions, which said the same thing twice.

Assessment

Who checked what, how, when, with which result and which evidence. The method is described through a registered facet.

Takes overAssessment plan and assessment results.

Finding

A gap against a requirement or a statement: state, actions with due dates that know their calendar, and Deviations. A Deviation is one typed record with one state machine (investigating, pending, approved or withdrawn) wherever something is weakened or accepted.

Takes overThe POA&M and four FedRAMP extensions that each encoded the same state machine.

Signature

Attestation

Binds the semantic digests of the objects, the digest of the content manifest and the digest of the rendered document a person signed, in a DSSE envelope. What the machine checked and what the authorizing official signed cannot drift apart unnoticed.

Takes overThe signed PDF whose relation to the data nobody can verify.

Proposed

Check CP-CHECK-1

A typed contract of the facts a collector reports, and a flat conjunction over eleven comparators that decides pass or fail. Collector code sits in a facet. What does not fit this form stays a manual check. Recorded verdicts are recomputed by the validator, and evidence files are named by their SHA-256.

Would take overAudit procedures as prose, such as the 291 automated rules of the CIS Ubuntu 24.04 Benchmark that arrive as text a person must read.

Advice pack CP-ADVICE-1

Not a type: a bundle whose manifest names publisher, pack and release, and whose objects are Components only. A vendor's recommendations are capabilities on its Component: the requirement, the clauses, the text, and suggested parameter values. Importing a pack changes no object a set already holds. The vendor's manifest stays in the set under the SHA-256 of its bytes, so the same file is not imported twice and advice edited after import is reported. A recommendation counts for nothing until an Implementation of the user's own cites it.

Would take overThe one use of component definitions worth keeping: a vendor supplies text for consideration and cannot change controls or assessments.

03 Binding force

The modal verbs have an order, and tailoring is checked against it

Three corpora converge on the same field: modal_verb in Grundschutz++ (1,006 instances), force in FedRAMP CR26, the style guide of the ISM. In JASCON it is a kernel code with a partial order.

Obligations
unspecifiedmayshouldmust
Prohibitions
unspecifiedshould-notmust-not
Restriction (German DARF NUR)
maymay-only

A move along an arrow is monotone and free. A move against it is an easing, and a move between the chains is an axis change. A Tailoring published by the authority may make either; a consumer's Tailoring needs a recorded Deviation with an approver for both. Excluding a requirement is plain selection and needs no Deviation, because baselines consist of exclusions.

an operation with a typed deadline

  "statement-id": "s1",
  "parameter": "iir-deadline",
  "value": { "type": "duration", "num": 6, "unit": "hours" }
}

Parameters are typed

Strings, integers, canonical decimals, booleans, dates, URIs and codes, with choice, list and range as containers. Durations are either elapsed time or a calendar period that names its calendar, because a deadline in business days means nothing without one. A {param:name} token in prose must resolve to a declared parameter, which makes the 216 drifting placeholders of the census impossible to write.

04 Extension

Two members on every object carry everything else

More than 70 % of the 22,000 props counted in three national catalogues imitate kernel mechanics: membership, ordering, history, aliases, clause structure. The remainder gets a contract.

facets

7 in the standard library

A facet name resolves to a JSON Schema pinned in the bundle's manifest by exact version and digest. Its descriptor declares what it changes: assessment, tailoring, selection or rendering. A tool validates the payload against the pin. A tool that meets a semantics-bearing facet it does not implement stops and prints the reason.

Why: three tools that meet one unknown prop today do three different things, and all three claim conformance.

annotations

excluded from digests

A flat map for tool bookkeeping and rendering hints: a tracker id, a web name, a do-not-link flag. Annotations are outside every compliance computation and outside the semantic digest by definition, so nothing conformant can read meaning from them.

Why: tools need a place for their own notes that cannot turn into a second, unvalidated vocabulary.

05 Integrity

Two digests per object

A publication is a bundle: objects, pinned facet schemas, renderings and one content manifest. The attestation lies beside the manifest, since nothing signed can contain its own signature.

06 Conformance

Three tiers, each with receipts

A tier claim is checked against the public conformance corpus. A claim without corpus results is a datasheet.

TierPromises
CoreSchema validation of every type, sealed operation, package digests, local reference resolution, and preservation of everything unknown. No semantic computation.
PortableFacet validation against pins with the fail-closed gate, semantic digests, deterministic tailoring resolution, lawful bundle composition, risk coverage.
AuthorityPublication duties: governed stable identifiers, alias and lineage records on every reorganisation, both digests per object, a deprecation lifecycle.

07 For OSCAL 1.x users

Where everything went

OSCAL is the origin of this work and the format JASCON reads and writes. Catalogue bundles export to OSCAL 1.2.2; what OSCAL has no construct for rides in namespaced props and returns on import.
