02 モデル

文書は、グラフをレンダリングしたものになる

入れ子の浅い 11 のオブジェクト型があり、それぞれがグローバル識別子、バージョン、2 つの SHA-256 ダイジェストを持ちます。実測したすべてのフレームワークが必要とするものは、固定されたカーネルに置かれます。1 つのフレームワークだけが必要とするものは、スキーマを持つ登録済みのファセットに置かれます。

カーネル

条項ごとの拘束力、型付きのパラメータと期限、所属関係、別名、履歴。

規範的で、閉じています。変更はバージョンの更新とともに行われます。

ファセット

フレームワーク固有の語彙：ドイツ語のステートメント文法、800-53A の評価目的、保護目標。

登録制で、スキーマが固定されています。知らないファセットに出会ったツールは、理由を示して停止します。

アノテーション

あらゆるコンプライアンス計算の対象外であり、セマンティックダイジェストにも含まれません。

03 何が変わるか

コンプライアンスデータで計算できるようになると、何が起きるか

GRC エンジニアリングは、コンプライアンスを他のエンジニアリング成果物と同じように扱います。バージョン管理し、型を付け、テストし、署名するのです。そのためには、プログラムが推論できるデータが必要です。ここでは 8 つの帰結を、それぞれの仕組みと根拠の状況とともに示します。9 つ目の帰結である機械によるチェックは、次のセクションで単独で取り上げます。

ISO/IEC 27001 6.1.3 d2 つのバンドルで実測

適用宣言書が計算で求められるようになる

Risk は、その所有者、対応の決定、その決定を担う条項を明示します。これを受けて、プリミティブ risk-coverage が、評価済みのリスクのどれにも基づかない選択済みの要求事項をすべて列挙します。これまで監査人は、これをスプレッドシートから抜き取りで確認していました。

仕組み：2.0.0 候補の Risk 型。サンプルバンドルでは、バリデータが選択 3 件、正当化 1 件、未カバー 2 件と報告し、その 2 件を名指しします。

Mapping実測

クロスウォークは作成者を持つデータになる

Mapping はそれ自体が独立したオブジェクトで、個々のステートメントの単位まで、ソース、ターゲット、関係、確度、来歴を持ちます。第三者のクロスウォークはどちらのカタログにも属さず、バージョン管理や差分比較ができ、異論を唱える対象にもなります。

仕組み：NIST IR 8477 の関係コード。1.0.0 のコーパスに 1,008 件の Mapping。

Tailoring実測

上流のリリース後も有効なテーラリング

Tailoring は Set によって選択し、識別子によって変更します。この要求事項の、このステートメントの、このパラメータ、という具合です。強化は自由に行えます。緩和には記録された Deviation が必要で、法助動詞の半順序に照らしてチェックされます。

仕組み：8 つの閉じた操作、決定的な解決、マージ規則なし。

Attestation実測

再パッケージ後も有効な署名

証明が結び付けるのは、セマンティックダイジェストです。ファイルのインデントを変えたり、トラッカーの ID を追加したりしても、判定は Semantic Match です。法助動詞を変えると、判定は Tamper になります。

仕組み：バイト列に対するパッケージダイジェストと、正規化したコンテンツに対するセマンティックダイジェスト。DSSE エンベロープ、Ed25519。下で試せます。

04 チェック

評価者が機械であるとき

0 か 1 で終了するスキャナーは、しきい値を隠し、テーラリングを無視します。Check は、コレクターが報告するファクトと、判定を下す比較を公開し、実行記録には観測値が残ります。

11 番目の型、2.0.0 候補 {{ n.check_vectors }} 件のテストベクトルが 3 つの実装で合格
  • 合格基準は Tailoring が決める。基準は要求事項のパラメータに結び付いています。パラメータを厳しくすると、コードを変えることなく、昨日の観測値があらためて判定されます。
  • 判定は再計算される。バリデータは記録されたすべての観測値について基準を評価し、結果が食い違う行を却下します。
  • フリートには割合が示され、判定が甘くなることはない。多数のリソースにまたがるチェックは、すべてが合格した場合にだけ合格します。すべてが評価され、結果は「200 件中 12 件が不充足（6%）」のように表示されます。
  • 実測による適合度：ComplianceAsCode の CIS Ubuntu 24.04 プロファイルにある 510 のルールのうち、481 が宣言的な形式に収まります。残りの 29 は手動のままです。

バイト列を変え、次に意味を変える

リポジトリにあるサンプルの要求事項と、そのコンテンツマニフェストに記録された 2 つのダイジェストです。編集するか、ボタンを使ってください。どちらのダイジェストも、バリデータと同じ規則でブラウザ内で計算されます。

何かを変更する

パッケージダイジェスト変更なし

セマンティックダイジェスト変更なし

06 ツール

サーバーなしで動くアプリ

JASCON アプリは、ビルド工程もバックエンドも持たない一連のブラウザページです。読み込んだバンドルはブラウザ内にとどまります。タブは作業の順序に沿って並んでいます。

  • Import ページで OSCAL のカタログまたはプロファイルを取り込みます。Grundschutz++ 用のルールは、同梱のバンドルをオブジェクト単位で、セマンティックダイジェストまで一致する形で再現します。
  • Risk、Tailor、Map、Implement、Assess：どのページも実際のオブジェクトを作業セットに書き込み、オブジェクトごとに両方のダイジェストを付けたバンドルをエクスポートします。
  • 下書きはモデルから、判定はカーネルから。キーを入力すると、2 つのページで言語モデルに問い合わせることができます。下書きはカーネル規則で判定され、採用したときにだけ保存されます。

07 根拠

すべての主張は、実際のカタログで通用しなければならない

本プロジェクトは、根拠のゲートを 1 つずつ通過して進みます。仕組みが仕様に入るのは、公開されたカタログがそれを必要とするときです。また、このサイトの数値は、実測値であるか、そうでなければ別のものとして明示されています。

4 つの立場と、それぞれの最初の一歩

どれも 1 日で済み、誰の許可も要りません。

フレームワークを公開する方

発行機関と標準化団体

カタログの構造はそのまま保たれます。ベースラインは Set に、バリエーションは Tailoring に、独自の語彙はスキーマを持つファセットになります。

最初の一歩名前空間を決め、Set を 1 つ書き、要求事項を 10 件エンコードし直してみてください。あるいは、Import ページでご自身のカタログを開いてください。

ツールを開発する方

GRC ベンダーとプラットフォームチーム

JSON Schema は 1 つ、シリアライゼーションも 1 つ、そして失敗時に論拠を出力する 10 のプリミティブ。メタスキーマもプロファイル解決もありません。

最初の一歩適合性コーパスをクローンし、お使いの言語でバリデータを書いてください。審判役はテストベクトルです。

コンプライアンスを運用する方

GRC エンジニア、CISO、ISMS 責任者

リスク登録簿、適用宣言書、実装ステートメント、指摘事項を、リポジトリ内のファイルとして持ち、コードと同じようにレビューできます。

最初の一歩アプリで SP 800-53 か Grundschutz++ を読み込み、リスクを 3 件書いて、カバレッジを確認してください。

評価または調達をする方

監査人、評価者、調達担当

承認された内容を、ご自身のマシンでオフラインのまま検証できます。PowerShell のバリデータに必要なのは、素の Windows マシンだけです。

最初の一歩供給者にバンドルを求め、それに対してバリデータを実行してください。コーパスでの結果を伴わない適合の主張は、ただのデータシートとして扱ってください。
