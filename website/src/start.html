Get started

From a browser tab to a validated bundle

Six steps, in the order most people take them. The first needs a browser. The second needs Python or a Windows machine. None needs an account, a server or a licence key.

Open a catalogue you know

The app loads a bundle from a link and keeps it in your browser. Start with the framework you work with: the object browser builds its filters from the data, so SP 800-53 offers families and baselines and Grundschutz++ offers modal verbs, protection goals and target objects.

The example bundle of the handbook holds one object of every type, including a Risk, two Tailorings and two Checks: open the example bundle. A single-file reader without a folder around it exists as well; download it and drop a bundle folder on it.

Run the reference validator

The validator runs the {{ n.vectors }} conformance vectors, then re-verifies every object of the shipped bundles with both digests. The last line reads ALL GREEN or lists each failure with its rule and its reason.

Pass one or more bundle folders to validate your own content. --require-risk-basis turns a selected requirement without a justifying risk into a failure.

On Windows the PowerShell twin does the same on PowerShell 5.1 with nothing installed. It takes minutes where Python takes seconds.

Python, with uv
git clone https://github.com/christoph-puppe/JASCON.git
cd JASCON
uv run --no-project --with jsonschema python jascon/scripts/validate_core.py
Python, with pip
pip install jsonschema
python jascon/scripts/validate_core.py
# your own bundle:
python jascon/scripts/validate_core.py path/to/your-bundle
Windows PowerShell 5.1, no install
powershell -ExecutionPolicy Bypass -File jascon\scripts\validate_core.ps1

Write a first requirement

Choose a prefix under a domain you control and keep it. Identifiers are compared as strings and never fetched, so the address does not have to serve anything.

Split the text into statements where the binding force, the obligated party or a parameter changes. Declare each parameter with a type and refer to it in the prose with {param:name}.

The Browse page of the app has a form for this under "Write requirements and sets". It declares the parameters it finds in the prose. The Home page exports the working set as a bundle with a manifest and both digests per object.

Bring your OSCAL, and take it back out

The Import page of the app reads an OSCAL catalogue or profile and reports every rule it applied. Rule sets exist for Grundschutz++, SP 800-53 and CIS Benchmarks; a catalogue of another shape goes through the generic rules, which keep what the kernel has no field for in a facet under your namespace and drop nothing without a line in the report. For batch work the repository holds eleven converters in Python, one per measured corpus, on a shared library.

In the other direction, export_oscal.py writes OSCAL 1.2.2 catalogues. The exports of the shipped bundles lie beside them under converted_examples/*/oscal-export/. What OSCAL has no construct for (modality, obligated parties, overlapping membership) travels in namespaced props and returns on import.

Add risks and compute the coverage

Load a catalogue, select a baseline with a Tailoring, and write the risks that justify the selection on the Risk page. The Coverage view lists every selected requirement that no assessed risk names.

Two prototype risk catalogues help with the first pass: 24 typical risks of office IT and 23 of an industrial plant, in English and German, each with suggested SP 800-53 controls. Import copies an entry into a Risk of your own; the decision stays yours.

Work with a coding agent

The folder jascon/ is a skill for Claude: the handbook as fourteen numbered requirements, the kernel schema, the conformance vectors, the converters and a worked example bundle. An agent that has it writes objects against the schema and runs the validator on its own output.

The division of labour is the one the app uses: a model drafts, the kernel rules decide, a person accepts.

install the skill
# for your user
cp -r jascon ~/.claude/skills/jascon
# or for one project
cp -r jascon .claude/skills/jascon
