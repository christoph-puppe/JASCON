The data layer for GRC engineering

JASCON writes standards, tailoring, risks, implementations, assessments and attestations as one graph of typed, content-addressed JSON objects. A Statement of Applicability becomes a computation, a machine check becomes something a second party can recompute, and a signature still verifies after the bundle is repackaged.

02 The model

Documents become renderings of a graph

Eleven shallow object types, each with a global identifier, a version and two SHA-256 digests. What every measured framework needs sits in a fixed kernel. What one framework needs sits in a registered facet with a schema.

Kernel

Binding force per clause, typed parameters and deadlines, membership, aliases, history.

Normative and closed. Changes ride a version.

Facets

Framework vocabulary: the German statement grammar, 800-53A objectives, protection goals.

Registered, schema-pinned. A tool that does not know one stops with a reason.

Annotations

Tracker ids, rendering hints, tool bookkeeping.

Outside every compliance computation and outside the semantic digest.

Failures are made unrepresentable where that is possible. A parameter token in prose must name a declared parameter. A tailoring operation addresses a statement by identity, so an upstream erratum cannot repoint it.

03 What changes

What follows when compliance data can be computed on

GRC engineering treats compliance like any other engineering artefact: versioned, typed, tested and signed. That needs data a program can reason about. Eight consequences, each with its mechanism and the state of its evidence. A ninth, the machine check, has the next section to itself.

ISO/IEC 27001 6.1.3 dmeasured on two bundles

The Statement of Applicability becomes a computation

A Risk names its owner, its treatment decision and the clauses that carry that decision. The primitive risk-coverage then lists every selected requirement that rests on no assessed risk. An auditor used to sample that from a spreadsheet.

Mechanism: the Risk type of the 2.0.0 candidate. On the example bundle the validator reports 3 selected, 1 justified, 2 uncovered, and names the two.

Mappingmeasured

A crosswalk is data with an author

A Mapping is an object of its own: source, target, relationship, confidence and provenance, down to the single statement. A third party's crosswalk belongs to neither catalogue and can be versioned, diffed and disputed.

Mechanism: relationship codes from NIST IR 8477. 1,008 Mappings in the 1.0.0 corpus.

Tailoringmeasured

Tailoring that survives an upstream release

A Tailoring selects by Set and changes by identity: this requirement, this statement, this parameter. Strengthening is free. Weakening needs a recorded Deviation, checked against a partial order of the modal verbs.

Mechanism: eight closed operations, deterministic resolution, no merge rules.

Attestationmeasured

A signature that survives repackaging

An attestation binds semantic digests. Re-indent a file or add a tracker id and the verdict is Semantic Match. Change a modal verb and it is Tamper.

Mechanism: package digest over the bytes, semantic digest over the canonical content; DSSE envelope, Ed25519. Try it below.

Kernel rulesmeasured

Valid implies checkable

A {param:} token must name a declared, typed parameter. A facet pins its schema and declares which computations it changes. The converter built on these rules found 781 list values that a national catalogue in production packs into single comma-separated strings.

Mechanism: closed shapes, bound tokens, fail-closed facets.

textmeasured

One requirement, every language

Every human-readable field is a map from BCP 47 language tag to text. A requirement in German and English is one object with one identifier, which is what NIS2, DORA and the CRA will need across the Union's official languages.

Mechanism: the text primitive. The Grundschutz++ bundle carries de.

Implementationmeasured on one corpus

Inheritance with a named basis

A SaaS on a PaaS on an IaaS: every inherited edge names the upstream component and the specific authorization it leans on. Responsibility is typed per statement as provider, customer, shared or inherited.

Mechanism: one Implementation edge with inherited-from and basis-ref, checked link by link.

Exitmeasured

The way out is built in

Catalogue bundles export to OSCAL 1.2.2 that validates against NIST's schema and re-imports to the same digests. The reference validator is one Python file of {{ n.python_lines }} lines, and conformance is decided by public vectors.

Mechanism: export_oscal.py, the conformance corpus, Apache 2.0.

04 Checks

When the assessor is a machine

A scanner that exits with 0 or 1 hides its threshold and ignores the tailoring. A Check publishes the facts a collector reports and the comparisons that decide, and the run record carries the observation.

eleventh type, 2.0.0 candidate {{ n.check_vectors }} vectors pass in three implementations
  • The Tailoring sets the pass mark. The criteria bind a parameter of the requirement. Tighten it and yesterday's observation is judged again, without a change to the code.
  • A verdict is recomputed. The validator evaluates the criteria on every recorded observation and rejects a row whose outcome differs.
  • A fleet gets a share, never a softer verdict. A check over many resources passes only if every one passes. All are evaluated, and the result reads "12 of 200 not satisfied (6 %)".
  • Measured fit: 481 of the 510 rules in the CIS Ubuntu 24.04 profiles of ComplianceAsCode fit the declarative form. The other 29 stay manual.

06 The tool

A working app without a server

The JASCON app is a set of browser pages with no build step and no backend. A bundle you load stays in your browser. The tabs follow the order of the work.

  • Import an OSCAL catalogue or profile. The Grundschutz++ rules reproduce the shipped bundle object for object, by semantic digest.
  • Risk, Tailor, Map, Implement, Assess: every page writes real objects into the working set and exports a bundle with both digests per object.
  • Drafts from a model, verdicts from the kernel. Two pages can ask a language model once you enter a key. A draft is judged by the kernel rules and saved only when you take it.

07 Evidence

Every claim has to survive real catalogues

The project moves through evidence gates. A mechanism enters the specification when a published catalogue demands it, and a number on this site is either measured or labelled as something else.

Vendor recommendations as a bundle of Components that an import cannot use to change requirements or assessments. No new type, eleven rules, {{ n.advice_vectors }} vectors and a worked pack, green in both validators. More on advice packs.

08 Who it is for

Four chairs, one first move each

Each of these costs a day and needs nobody's permission.

You publish a framework

Authorities and standards bodies

Your catalogue keeps its structure. Baselines become Sets, variants become Tailorings, your vocabulary becomes a facet with a schema.

First moveChoose a namespace, write one Set and re-encode ten requirements. Or open your catalogue in the Import page.

You build tools

GRC vendors and platform teams

One JSON Schema, one serialization, ten primitives with a rationale that prints on failure. No metaschema and no profile resolution.

First moveClone the conformance corpus and write a validator in your language. The vectors are the referee.

You run compliance

GRC engineers, CISOs, ISMS owners

Your risk register, Statement of Applicability, implementation statements and findings as files in a repository, reviewed like code.

First moveLoad SP 800-53 or Grundschutz++ in the app, write three risks and read the coverage.

You assess or buy

Auditors, assessors, procurement

You verify what was approved, on your own machine, offline. The PowerShell validator needs a stock Windows box and nothing else.

First moveAsk a supplier for a bundle and run the validator on it. Treat a conformance claim without corpus results as a datasheet.

One maintainer and no third-party user yet

That is the state on {{ facts.measured.date }}, and the reason this site exists. Three contributions would change it most: a validator written by someone who did not write the specification, a catalogue converted by its own publisher, and objections that come with counts.
