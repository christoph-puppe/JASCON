?What is checked, and what is not

Checked, each rule ported from validate_core.py and run against its conformance vectors:

The manifest: its shape, and that it pins the kernel its content needs. Every object: that it matches exactly one kernel type, that an optional list is absent instead of empty, that statement ids are unique, that every {param:} token is declared, that a facet keyed by statement names statements that exist.

Integrity: both digests of every object and the digest of every pinned file against the manifest. An object edited in this app is reported as a note, because the export writes a new manifest.

References: every reference that must resolve inside the bundle does, with the right type; Set membership has no cycle; a mapping's scope names statements that exist.

Tailorings: two operations on one target; a weakening without a Deviation at consumer tier; a parameter value of the wrong kind. Facets: every payload against the standard descriptor or the pinned schema; an unregistered facet fails.

Risks and scales: RISK-1 to RISK-14 with the coverage of the selected requirements, SCALE-1 to SCALE-4 with the matrix.

Not checked: conditional-apply instances, the composition of two bundles, and signatures (DSSE envelopes). The tier of a Tailoring is derived without verifying a signature. For these, and as the reference in every case of doubt, run jascon/scripts/validate_core.py on the exported bundle.
